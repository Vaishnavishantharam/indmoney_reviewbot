# IND Money — Weekly Review Pulse

Turn recent **Google Play Store** reviews for **IND Money** into a one-page weekly pulse: top themes, user quotes, and action ideas, with an optional email draft sent to yourself.

- **Product:** IND Money (`in.indwealth`)
- **LLM:** Groq
- **Review source:** [google-play-scraper](https://www.npmjs.com/package/google-play-scraper) (public data only)

## Fetching reviews (Phase 1)

Reviews are stored in `reviews/reviews_YYYY-MM-DD.json` and `.csv`. Each row has: `index`, `rating`, `title`, `text`, `date`, `dateDisplay` (e.g. "June 22, 2025"), `helpfulCount` (e.g. "354 people found this review helpful"). No PII.

Code is organized **phase-wise**: `phase1/`, `phase2/`, … (see ARCHITECTURE.md).

**Phase 1 — Fetch reviews (Python, no Node required):**

```bash
pip install -r requirements.txt
python3 phase1/fetch_reviews.py
```

Or: `npm run fetch-reviews:py`

**Phase 1 — Node.js** (if you have npm): `npm run fetch-reviews` or `npm run fetch-reviews:playwright`

## How to re-run for a new week

1. **CLI:** Set `WEEKS_BACK` (8–12) and run:
   ```bash
   npm run weekly    # fetch reviews → generate themes → one-pager
   npm run email     # draft and send email (or save draft only)
   ```
2. **UI:** Open the web app → choose “Weeks back” (8–12) → **“Generate one-pager”** → then **“Send email to me”** if needed.

## Theme legend

Themes are generated by the LLM from the current review set. Typical labels you might see (examples):

| Theme label   | Meaning |
|---------------|---------|
| **UX / Usability** | Navigation, clarity, ease of use |
| **Performance**   | Speed, crashes, lag |
| **Features**      | Requests or feedback about functionality |
| **Support**       | Customer support, resolution |
| **Bugs / Issues** | Defects, errors, login problems |

Exact themes will vary each run; see `output/theme-legend.md` (or the UI) after a run for the current week’s definitions.

## Setup (high level)

1. Clone repo, `npm install`.
2. Copy `.env.example` to `.env`; set `GROQ_API_KEY`, optional `SEND_TO_ALIAS` and SMTP for email.
3. Run pipeline via CLI or UI (see ARCHITECTURE for full stack and file layout).
